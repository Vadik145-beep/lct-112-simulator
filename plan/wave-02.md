# Волна 2. Движки оценки

**Срок:** 16-17.09. **PRD:** разделы 9.1, 9.2 (оценка), 9.3 (оценка).

## Цель

Два движка оценки как чистые функции с полным табличным покрытием. Интерфейса ещё нет, но оценка
уже правильная и быстрая. Это сердце продукта, поэтому отдельная волна.

## Вход

Волна 1 закрыта: справочники и типичные ошибки в базе.

## Задачи

### Общее (`app/domain/evaluation/`)
- [ ] Структура результата: `total`, `passed`, `components{score,max,items…}`, `errors[]`, `methods{}`.
- [ ] Перенормировка при недоступном провайдере (`not_checked`).
- [ ] Веса занятия масштабируют максимумы, сумма 100.
- [ ] Нормализация текста: регистр, `ё→е`, пунктуация, типы улиц; тесты.

### Режим «Реагирование на карточку» (`card_response`)
- [ ] Решение (30), время принятия от «Добавлена» (20), цепочка статусов (20), комментарии и наряд (15), типичные ошибки (10), грамотность (5).
- [ ] Детекторы из PRD 9.1: `status_mismatch`, `competence_refusal`, `late_primary`, `no_status`, `empty_reject_comment`, `incomplete_comment`, `progress_missing`, `profile_refusal`, `duplicate_accepted`, `wrong_accept_unfixed`. Каждый с тестом на примере из памятки (стр. 28-31).
- [ ] Машина статусов: `allowed_next`, «Не принята» → только «Принята», финальные закрывают, исключение 103, `requires_comment`, `requires_order_number`. Недопустимый переход даёт понятную ошибку.

### Режим «Приём вызова» (`call_intake`)
- [ ] Опросная карта (25): полный путь, верный тип с неверным нижним уровнем, верная группа.
- [ ] Флаги и службы (10) через `resolve_services`; адрес (15); обязательные вопросы (15); описание (10); время (10); типичные ошибки (5): `address_not_asked`, `dropped_call_unmarked`, `region_not_checked`; грамотность (10).

### Тесты (табличные, поведение, не текст исходника)
- [ ] Идеальная попытка → 100 в обоих режимах.
- [ ] «Не принята» без комментария; пропущенный статус; лишний статус; недопустимый переход.
- [ ] Время 30, 45, 60 с при нормативе 30 → 20, 10, 0.
- [ ] Улица «ул. Берзарина» против «улица Берзарина» → совпадение; «Берзарино» → нет.
- [ ] LanguageTool недоступен → грамотность `not_checked`, итог перенормирован.
- [ ] Веса занятия: грамотность 0 → итог из остальных.
- [ ] Замер: оценка без LLM быстрее 300 мс (тест с таймером).

### Фикстуры
- [ ] 5 эталонных сценариев `card_response` и 5 `call_intake` из билетов (руками, с эталонами) в `data/seed/scenarios/` как JSON по схеме PRD 9.2 и 9.3. Они же пойдут в seed волн 3 и 7.

## Проверка

```bash
pytest backend/tests/domain/evaluation -q
pytest backend/tests/domain/evaluation/test_speed.py -q
```

- [ ] Все тесты зелёные, покрытие детекторов 100% (каждый детектор хотя бы в двух тестах: срабатывает и не срабатывает).
- [ ] Пример из PRD 9.2 даёт ожидаемые составляющие.

## Показать

Вывод `pytest -v` и один JSON результата оценки с объяснением по составляющим.

## Если не получается

Смысловая близость через e5 тянет медленно на ноутбуке: временно TF-IDF, e5 включить в волне 5
вместе с моделями.
