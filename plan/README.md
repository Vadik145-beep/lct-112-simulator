## Порядок работы над задачей

Полные правила в [CLAUDE.md](../CLAUDE.md). Коротко:

1. Каждая волна заведена как **issue** в репозитории (метка `wave`). Взять: `gh issue edit <N> --add-label in_progress`.
2. Работа только в **отдельном worktree** на ветке от свежего `main`:
   `git worktree add ../lct-worktrees/<имя> -b wave-NN/<имя> origin/main`.
3. В `main` только через **pull request** с `Closes #N`. Один PR на одну issue. Второй участник
   смотрит PR хотя бы бегло.
4. Мы работаем **параллельно**: Вадим ведёт волны, Константин треки G и K. Перед началом всегда
   `git fetch`, при конфликте `git rebase origin/main` у себя в ветке.
5. После мержа worktree удаляется, issue закрывается автоматически.

## Правила работы по волнам

1. **Одна волна за сессию.** Открыть агента в worktree волны, вставить промпт из
   [PROMPTS.md](PROMPTS.md). Агент читает PRD, файл волны и `docs/PROGRESS.md`, делает задачи,
   гоняет проверки, коммитит.
2. **Волна закрыта, когда все пункты раздела «Проверка» зелёные** и Вадим сам прошёл раздел «Показать»
   в браузере. Не «почти»: если что-то красное, это пишется в `docs/BLOCKERS.md`, и волна остаётся
   открытой.
3. **После волны Вадим руками проверяет в браузере** то, что написано в «Показать», и пишет в чат
   Константину одной строкой: «волна N закрыта» или что не так. Скриншот в `docs/screenshots/wave-NN/`.
4. **Не забегать вперёд.** Если агент предлагает сделать что-то из следующих волн, ответ «нет, это
   волна N+2».
5. **Если волна не закрывается за день,** урезать пункты, помеченные (P2), и идти дальше. Пункты без
   пометки обязательны.
6. **План живой.** Нашли, что не учли: добавить пункт в файл волны отдельным коммитом
   `plan: …`, не в голову.
7. Коммиты по-русски с номером issue. Нигде в репозитории нет упоминаний ИИ-ассистентов и
   инструментов генерации кода: код читают эксперты заказчика.

## Что нужно Вадиму, чтобы сделать всё за один присест каждой волны

- Компьютер: 16 ГБ памяти и больше, Docker Desktop с 8 ГБ, свободных 40 ГБ на диске (модели и образы).
- Установлено: Git, Docker Desktop, Node 22, Python 3.12, `uv`, Claude Code (Opus, auto).
- В `data/organizers/` лежат все файлы организаторов (список в PRD, раздел 1.2).
- Для волны 5 и дальше: скачанные модели (`scripts/fetch_models.sh`, нужен интернет один раз,
  около 10 ГБ).
- Для волны 6: гарнитура, Chrome; для последнего шага настольный IP-телефон у Константина.
- Аккаунт GitHub с правом записи в репозиторий.

## Определение «готово» для всего проекта

- Новый человек по `README.md` поднимает систему одной командой и входит по логину и паролю.
- Демо-сценарий из PRD раздел 5 проходит без подсказок и без консоли.
- `docs/REQUIREMENTS_MATRIX.md` заполнена, каждый пункт ТЗ со статусом.
- Стенд для жюри работает и не трогается с 29.09 по 14.10.
