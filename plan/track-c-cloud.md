# Трек C. Облачный голос: живой заявитель на облачных моделях

**Ведёт:** Вадим. **Старт:** сразу, параллельно волне 11; не блокирует волны 11-12.
**Срок:** рабочая версия к 24.09, замеры и видео к 26.09. **Решение:** Константин, 19.09.

## Зачем

Сейчас заявитель на CPU отвечает только утверждёнными репликами (`select`), с задержкой около
1,7 с голосом и ровным синтезированным голосом. Это честно и соответствует ТЗ, но не удивляет.

Трек C добавляет третий способ провести тот же разговор: **свободная речь заявителя с эмоцией,
ответ примерно через секунду, перебивание**, на облачной связке, которая уже работает
в продакшене на телефонных звонках у Константина:

| Звено | Сервис | Модель | Почему она |
|---|---|---|---|
| Распознавание (STT) | Soniox, потоковый WebSocket | `stt-rt-v5` | лучшая точность на русском из испытанных, сама находит конец фразы |
| Ответ заявителя (LLM) | OpenAI, потоковый API | `gpt-4o-mini` | быстрый первый токен, дёшево, держит роль |
| Запасная LLM | Groq, OpenAI-совместимый API | `openai/gpt-oss-120b` | тот же протокол, ещё быстрее первый токен |
| Синтез (TTS) | ElevenLabs, потоковый WebSocket | `eleven_flash_v2_5` | первые звуки за 150-300 мс, живой русский голос |

Резерв распознавания в продакшене Deepgram `nova-3`; здесь он не нужен, запасной путь описан ниже.

Показ на питче: **один и тот же билет трижды**. Закрытый контур на CPU (`select`), облачный
голос (`cloud`), при наличии GPU живой режим трека G. Жюри видит, что архитектура одна, меняется
только провайдер, а заказчик выбирает контур под свои требования.

## Граница с ТЗ, это важно

PRD раздел 2 запрещает внешние ИИ в продукте. Трек C это **не замена продукта, а
демонстрационный режим** рядом с ним:

- включается только при `ALLOW_EXTERNAL_AI=true` и `CLOUD_VOICE_ENABLED=true`;
- при `ALLOW_EXTERNAL_AI=false` и включённом облачном голосе бэкенд **не стартует** с понятной
  ошибкой, как уже сделано для `LLM_DIALOG_URL`;
- стенд для технической экспертизы 30.09-14.10 работает с `ALLOW_EXTERNAL_AI=false`, режима там
  нет. Облачный голос живёт на отдельном экземпляре для показа или на записанном видео;
- в кабинетах уже есть плашка «Внешняя модель: не для закрытого контура»; в занятии с режимом
  `cloud` она видна и обучающемуся;
- в облако уходит голос оператора и выдуманные данные билета. Реальных персональных данных нет.
  Для показа говорит кто-то из команды.

## Как устроено

```
софтфон ── Asterisk ── snoop (только голос оператора) ── ExternalMedia RTP slin16
                                                               │
                             backend: CloudVoiceSession на один звонок
                                                               │
   PCM 16 кГц ──► Soniox WS (поток, конец фразы токеном <end>) ─┤
                                                               ▼
                     реплика оператора ──► OpenAI stream (роль и факты билета)
                                                               │ предложение готово
                                                               ▼
                             сверка с фактами ──► ElevenLabs WS (pcm_16000)
                                                               │
                  .sln16 на каждое предложение ──► ARI playback в мост звонка
```

Голос заявителя в распознавание не попадает: snoop слушает только канал обучающегося. Эха нет,
отдельное подавление не нужно.

Параллельно с потоковым ответом тот же облачный LLM одним коротким запросом размечает **темы**
реплики оператора, через уже готовые `select_messages` и `select_schema`. Стенограмма, темы и
оценка пишутся так же, как в `select`. Движок оценки не меняется.

## Шаги

### 0. Проверка доступа (первым делом, до кода)

- [ ] `scripts/cloud_voice_check.py`: по очереди Soniox (отправить 3 с тишины и 3 с речи из
  `data/seed`), OpenAI и Groq (одна реплика потоком), ElevenLabs (одна фраза в `pcm_16000`).
  Печатает для каждого: доступен или нет, текст ошибки, время первого ответа в мс.
- [ ] Если ответ «регион не поддерживается», записать в `docs/BLOCKERS.md` и написать
  Константину. Прокси подключается одной настройкой, код от него не зависит.

### 1. Настройки

- [ ] В `config.py` и `.env.example` (значения пустые, с комментариями):
  `CLOUD_VOICE_ENABLED`, `SONIOX_API_KEY`, `SONIOX_MODEL=stt-rt-v5`, `CLOUD_LLM_BASE_URL`
  (по умолчанию OpenAI), `CLOUD_LLM_API_KEY`, `CLOUD_LLM_MODEL=gpt-4o-mini`,
  `CLOUD_LLM_FALLBACK_BASE_URL`, `CLOUD_LLM_FALLBACK_API_KEY`,
  `CLOUD_LLM_FALLBACK_MODEL=openai/gpt-oss-120b`, `ELEVENLABS_API_KEY`,
  `ELEVENLABS_MODEL=eleven_flash_v2_5`, `ELEVENLABS_VOICE_MALE`, `ELEVENLABS_VOICE_FEMALE`,
  `ELEVENLABS_VOICE_ELDER`, `ELEVENLABS_VOICE_YOUNG`, `CLOUD_HTTPS_PROXY`,
  `CLOUD_FIRST_AUDIO_TIMEOUT_MS=2500`.
- [ ] `ai_service_urls()` учитывает облачные адреса, когда `CLOUD_VOICE_ENABLED=true`, поэтому
  `check_external_ai()` без правок отказывает в старте при `ALLOW_EXTERNAL_AI=false`.
- [ ] `DIALOG_MODES` получает `cloud`. Преподаватель видит пункт «Облачный голос» при создании
  занятия только когда режим включён. Иначе API отвечает 422 с понятным текстом.

### 2. Провайдеры (`backend/app/providers/cloud/`)

- [ ] `OpenAICompatibleChat` реализует протокол `ChatModel` (`complete_json`, `complete_text`,
  `available`) плюс `stream_text()`, который отдаёт текст по кускам. Один класс на OpenAI и Groq,
  разница только в адресе, ключе и модели. `complete_json` через `response_format`.
  После этого шага `select`, `generate` и `hybrid` работают и на облачной модели. Это быстрый
  промежуточный результат, его стоит показать отдельно.
- [ ] `SonioxStream`: WebSocket `wss://stt-rt.soniox.com/transcribe-websocket`. Первое сообщение
  JSON с ключом, моделью, `audio_format=pcm_s16le`, `sample_rate=16000`, `num_channels=1`,
  `language_hints=["ru"]`, `enable_endpoint_detection=true` и подсказками адреса билета в
  контексте. Дальше бинарные кадры по 20 мс. Отдаёт промежуточный текст и событие «фраза
  закончена» на токене `<end>`. Точные поля сверить с документацией Soniox на шаге 0.
- [ ] `ElevenLabsStream`: WebSocket
  `wss://api.elevenlabs.io/v1/text-to-speech/{voice_id}/stream-input?model_id=…&output_format=pcm_16000&language_code=ru`.
  Текст подаётся кусками по мере прихода из LLM, звук приходит base64 PCM 16 кГц, это ровно
  формат `sln16`. Для взволнованного заявителя `stability` 0,3-0,4, для спокойного 0,6.
- [ ] Выбор голоса по полу и возрасту заявителя из `VoiceSpec` билета: четыре настройки
  `ELEVENLABS_VOICE_*`, без идентификаторов в коде.
- [ ] Все клиенты ходят через `CLOUD_HTTPS_PROXY`, если он задан.

### 3. Роль заявителя

- [ ] Системный промпт собирается из того же, что `generate_messages`: ситуация, лист фактов,
  эмоция, правила. Добавить: говорить короткими фразами по 1-2 предложения, как испуганный
  человек по телефону; отвечать только на вопрос; не знать того, чего нет в фактах; не выходить
  из роли на провокации (`is_role_break` уже есть).
- [ ] **Страховка по фактам перед озвучкой** (как в треке G, шаг 4): каждое готовое предложение
  проверяется до отправки в синтез. Адреса, номера домов, числа и имена допустимы только из
  листа фактов. Выдумка заменяется утверждённой репликой «не знаю» из билета. Проверка по
  правилам и регулярным выражениям, без второго запроса к модели, чтобы не терять время.

### 4. Звонок (`telephony/calls.py`)

- [ ] Для занятия с `dialog_mode=cloud` звонок открывает `CloudVoiceSession`: кадры из
  `RtpReceiver` идут одновременно в Soniox и в детектор речи (детектор нужен для перебивания).
- [ ] На конце фразы: реплика оператора в стенограмму, потоковый ответ LLM, предложения по
  одному в ElevenLabs, каждое предложение пишется в `.sln16` и ставится в очередь проигрывания
  через уже готовый `_play`. Первое предложение отдавать в синтез, как только появилась точка
  или набралось около 40 символов до запятой.
- [ ] **Перебивание:** детектор услышал речь оператора, пока играет ответ. Тогда остановить
  проигрывание (добавить в `AriClient` остановку playback), отменить поток LLM и синтеза,
  пометить реплику в стенограмме как прерванную.
- [ ] **Запасной путь без облака:** нет первого звука за `CLOUD_FIRST_AUDIO_TIMEOUT_MS` или
  ошибка любого облачного звена. Тогда реплика берётся как в `select` на локальной модели, звонок
  не рвётся, в журнал занятия пишется событие «облако недоступно, ответ из утверждённых». Если
  упал OpenAI, сначала пробуется Groq.
- [ ] В событие каждой реплики добавить замеры: распознавание, первый токен LLM, первый звук,
  итог от конца фразы до начала звука. Мониторинг преподавателя показывает их строкой под
  репликой. На показе это отдельный «вау»: видно, куда уходят миллисекунды.
- [ ] (P2) Отдавать звук в звонок не файлами, а RTP через второй канал ExternalMedia в мосту,
  чтобы убрать запись файла и ожидание playback. Делать, только если после шага 6 медиана
  выше 1,3 с.

### 5. Без телефонии (микрофон браузера)

## Показать

Константину в браузере, потом записать видео для презентации (2-3 минуты):

1. Преподаватель создаёт занятие с билетом про ребёнка на велосипеде, режим «Утверждённые
   реплики». Звонок, три вопроса, заявитель отвечает по списку.
2. То же занятие в режиме «Облачный голос». Те же три вопроса, затем вопрос не по сценарию,
   затем перебить заявителя на полуслове. Замеры видны в мониторинге.
3. Разбор обоих звонков: одинаковая стенограмма, темы и оценка.
4. Слайд «Один интерфейс, три контура»: CPU в контуре, GPU в контуре, облако для пилота без
   своего железа. Таблица задержек из `PERFORMANCE.md`.

## Не делать

- Не подключать внешнюю платформу голосовых ассистентов целиком. Ей нужен публичный SIP до
  нашего Asterisk, она прячет стенограмму от оценки, а на питче это выглядело бы как чужой
  продукт. Связку собираем сами из трёх сервисов.
- Не менять движок оценки и формат стенограммы.
- Не трогать режимы `select`, `hybrid`, `generate`, `buttons` и их поведение по умолчанию.
- Не включать режим на стенде экспертизы.
