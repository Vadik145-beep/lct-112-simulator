# Волна 11. Доводка, нагрузка, документация

**Срок:** 25-26.09. **PRD:** разделы 14, 16 (фазы 5-6), 18.

## Цель

Продукт выглядит законченно, выдерживает нагрузку из ТЗ с цифрами, и по документации его может
поставить и проверить посторонний человек. Матрица соответствия ТЗ заполнена честно.

## Вход

Волна 10 закрыта.

## Задачи

### Доводка
- [ ] Полировка эмулятора по скриншотам: расположение, названия, цвета, шрифт; пустые и ошибочные состояния везде.
- [ ] Firefox и Яндекс.Браузер: полный проход обоих режимов.
- [ ] Кабинеты на 390 px: мониторинг, прогресс, отчёты.
- [ ] Полный e2e демо-сценария PRD раздел 5 (`e2e/demo.spec.ts`).
- [ ] Тест «нет внешних запросов»: Playwright перехватывает все запросы, разрешён только свой origin.
- [ ] `scripts/offline_bundle.sh`: `docker save` всех образов и моделей в архив, инструкция переноса, проверка на машине без интернета (Константин, трек K).

### Нагрузка (`load/`)
- [ ] Locust: 100 пользователей (журнал, карточка, статусы), p95 отклика; 20 обучающихся одновременно в режиме карточек с WebSocket.
- [ ] `scripts/bench_db_writes.py`: не меньше 100 записей событий в секунду.
- [ ] Отчёт на seed-истории быстрее 30 с.
- [ ] `docker kill backend` → сервис поднимается сам, сессии восстанавливаются (описать в `PERFORMANCE.md`).
- [ ] Все цифры в `docs/PERFORMANCE.md` с указанием машины, даты и команды.

### Документация (`docs/`)
- [ ] `ARCHITECTURE.md`: функциональная и компонентная архитектура, схемы, узлы стенда.
- [ ] `INSTALL.md`: сборка, установка одной командой, офлайн-перенос, стенд из узлов, восстановление из копии, подключение настольного IP-телефона.
- [ ] `METHODS.md`: методы обработки данных: импорт классификатора, OCR, оценка с формулами, детекторы, диалог по режимам, генерация, прогноз, свойство безопасности `select`.
- [ ] `LIMITATIONS.md`: условия и ограничения, включая `buttons` одним абзацем и внешние модели только для разработки.
- [ ] `LIBRARIES.md`: все библиотеки и модели с версиями и лицензиями.
- [ ] `USER_GUIDE.md`: по ролям со скриншотами.
- [ ] `REQUIREMENTS_MATRIX.md`: каждый пункт ТЗ организаторов → где сделано → как проверить → статус (сделано / частично с пояснением / не сделано). Многоуровневая аутентификация «частично», пока нет TOTP.
- [ ] `scripts/build_docs.sh`: DOCX и PDF через pandoc.
- [ ] `README.md` обновлён: демо-доступы, ссылки, скриншоты.

### Если осталось время (фаза E)
- [ ] TOTP для преподавателя и администратора (QR локально), матрица обновляется на «сделано».
- [ ] Prometheus + Grafana (профиль `monitoring`) с готовым дашбордом.

## Проверка

```bash
scripts/check.sh && npx playwright test
locust -f load/locustfile.py --headless -u 100 -r 10 -t 5m --html docs/load-report.html
scripts/build_docs.sh
```

- [ ] Все тесты зелёные.
- [ ] В матрице нет пунктов без статуса.
- [ ] Посторонний человек (Константин на чистой машине) по `INSTALL.md` поднимает систему и проходит демо без подсказок.

## Показать

Демо-сценарий целиком за 6 минут без запинок, репетиция вдвоём. `PERFORMANCE.md` с числами.
