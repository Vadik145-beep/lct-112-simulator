# Волна 6. Телефония

**Срок:** 19-20.09. **PRD:** раздел 9.5, 6.

## Цель

Из браузера обучающегося в софтфон приходит настоящий SIP-звонок от Asterisk, в трубке звучит
заявитель, речь обучающегося уходит в распознавание, ответ заявителя звучит в линию, звонок
записывается. Это закрывает пять пунктов ТЗ про VoIP.

## Вход

Волна 5 закрыта.

## Задачи

### Asterisk (`deploy/asterisk/`)
- [ ] Образ Asterisk 20+, профиль `telephony`, `network_mode: host` или явный диапазон RTP; конфиги `pjsip.conf` (транспорт WSS с TLS от нашего CA, UDP/TCP для настольных телефонов), `rtp.conf`, `ari.conf`, `http.conf`, `extensions.conf` со Stasis-приложением `trainer`.
- [ ] Шаблоны эндпоинтов: `stu-<логин>` для WebRTC (DTLS-SRTP, ICE, Opus), `phone-<логин>` для настольного телефона (G.722, PCMA).
- [ ] Генерация эндпоинтов из БД: при создании пользователя-обучающегося создаётся SIP-учётка, пароль шифруется в `users.sip_password_enc`; `GET /me/sip` отдаёт данные для регистрации.
- [ ] Запись каналов в WAV в `storage/recordings/`, путь в `attempts.recording_path`.

### ARI-клиент в бэкенде (`app/telephony/`)
- [ ] Подключение к ARI (HTTP + WebSocket), переподключение, `TELEPHONY_ENABLED`.
- [ ] `attempt.issued` в режиме приёма вызова → originate на эндпоинт обучающегося; события `call.ringing`, `call.answered`, `call.ended`.
- [ ] После ответа: проигрывание `opening`; snoop-канал или ExternalMedia → VAD (Silero на CPU) → фразы → STT → `DialogProvider` → воспроизведение ответа в канал.
- [ ] `POST /attempts/{id}/answer`, `/hangup`, `/no-contact`, `/call-dropped`; при `hangup` со стороны заявителя (сценарий «бросил трубку») Asterisk завершает звонок сам.
- [ ] Настройки телефонии в `settings` (адрес ARI, кодеки, запись) и на экране администратора (экран в волне 9, API сейчас).

### Софтфон в браузере
- [ ] JsSIP в панели вызова: регистрация при входе обучающегося, состояния «не подключён / готов / входящий / разговор / завершён», ответить, завершить, индикатор уровня микрофона, выбор устройства.
- [ ] Звук через `<audio>` с автовоспроизведением после жеста пользователя.
- [ ] `TELEPHONY_ENABLED=false`: панель работает через MediaRecorder и `/utterance`, логика та же.

### Замеры и тесты
- [ ] `scripts/bench_call.py`: через ARI создаёт тестовый звонок на локальный эндпоинт (SIPp или второй JsSIP в headless Chrome), подаёт WAV с вопросом, ждёт реплику; измеряет время от конца вопроса до начала ответа. Результат в `PERFORMANCE.md`.
- [ ] Статистика WebRTC (RTT, jitter) из браузера в `PERFORMANCE.md` как подтверждение 150 мс в локальной сети.
- [ ] Тест ARI-клиента на подменном сервере: originate, события, воспроизведение.

## Проверка

```bash
docker compose --profile ai --profile telephony up -d
pytest backend/tests/telephony -q
python scripts/bench_call.py
```

- [ ] В Chrome софтфон показывает «готов» после входа `student1`.
- [ ] Скрипт выдаёт попытку приёма вызова → в браузере звонок → ответ → слышен `opening`.
- [ ] Сказать в гарнитуру «скажите адрес» → в трубке реплика с адресом, в `attempt.dialog` тема `address`.
- [ ] После завершения в `storage/recordings/` есть WAV с обеими сторонами.
- [ ] Firefox и Яндекс.Браузер: регистрация и звонок работают.

## Если не получается

ICE в Docker на Windows капризничает: указать `external_media_address` и `external_signaling_address`
в `pjsip.conf` на IP машины, ограничить RTP диапазоном 10000-10100 и пробросить его. Совсем не
взлетает за день: закрыть волну с `TELEPHONY_ENABLED=false`, записать блокер, вернуться в волне 11
вместе с Константином. Настольный IP-телефон подключает Константин (трек K).
