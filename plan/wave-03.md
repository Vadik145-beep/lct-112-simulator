# Волна 3. Эмулятор ДДС: журнал и карточка

**Срок:** 17.09. **PRD:** разделы 13.1, 13.3, 13.4, 13.6, 9.2 (ход).

## Цель

Обучающийся видит журнал карточек своей службы, открывает карточку, ставит статусы во вкладке
службы, как в настоящем АРМ-112, и получает разбор. Занятие пока запускается скриптом seed, кабинет
преподавателя в волне 4.

## Вход

Волны 1-2 закрыты. Скриншоты АРМ-112 в `docs/reference/arm112/`.

## Задачи

### Бэкенд
- [ ] Таблицы `scenarios`, `scenario_versions`, `training_sessions`, `attempts`, `evaluations`, `session_events`.
- [ ] Выдача карточек в занятии: `attempt` со статусом «Добавлена», таймер 30 с от `issued_at`; при сложности 3 несколько карточек сразу.
- [ ] `GET /sessions/{id}/journal`, `POST /attempts/{id}/open` («Получена службой»), `POST /attempts/{id}/status` через машину статусов, `GET /attempts/{id}`.
- [ ] Статусы карточки: фоновая проверка каждые 5 с ставит «Не оповещено» после 30 с без первичного статуса; «Отказ», «Завершена».
- [ ] Оценка при финальном статусе или по «Завершить работу с карточкой»; в режиме с очередью сразу следующая карточка.
- [ ] WebSocket `/ws/sessions/{id}` с `session_events`, `after_seq`, события волны (`attempt.issued`, `attempt.received`, `attempt.status_changed`, `card.status_changed`, `attempt.evaluated`).
- [ ] Seed: 10 сценариев `card_response` из фикстур волны 2 и одно занятие `running` для `student1` с профилем службы.

### Фронтенд: журнал (по скриншоту стр. 12)
- [ ] Шапка: поиск, дата и крупные часы, имя и № АРМ, «автообновление», «создать новую карточку» (неактивна).
- [ ] Таблица «Список происшествий» с колонками как на скриншоте; раскрытие строки (службы со статусами, заявитель, информация, описание); красная индикация трёх статусов карточки; постраничность.
- [ ] Учебный таймер принятия на строке: цвет до 80%, предупреждение, красный, плюс значок.

### Фронтенд: карточка ДДС (по скриншотам стр. 23-24)
- [ ] Верхняя панель, левая колонка (заявитель, адрес, описание), правая (флаги, ЧС/ЧП, группа, признаки, «Класс.:»).
- [ ] Нижняя полоса «Службы» со вкладками; вкладка своей службы раскрывается синей панелью с историей «оп. N › время статус».
- [ ] Карандаш открывает строку: выпадающий список только допустимых статусов, «Номер наряда», комментарий, ✓ и ✕; при «Не принята» выбор причины и обязательный комментарий.
- [ ] Учебная панель справа: норматив, отставание, подсказки (выключаются), «Завершить работу с карточкой».
- [ ] Горячие клавиши `Alt+A`, `Alt+R`, `Ctrl+Enter`, `?`.
- [ ] Черновик комментария в `localStorage`, восстановление после перезагрузки.

### Фронтенд: разбор
- [ ] Итог, «Зачтено / Не зачтено», составляющие полосами, решение и цепочка статусов против эталона на шкале времени, сработавшие ошибки с названием и примером из памятки, комментарий с подчёркнутыми ошибками, «Следующая карточка».

### Фронтенд: кабинет обучающегося
- [ ] «Мои задания» с активным занятием крупно; «Справочник» с поиском по памятке и классификатору.

## Проверка

```bash
pytest backend/tests/api/test_attempts.py -q
npx playwright test e2e/dds.spec.ts
```

- [ ] e2e: `student1` открывает карточку → «Принята» → «Начало реагирования» с нарядом и комментарием → … → «Работы завершены» → разбор с баллом; вторая карточка «Не принята» с причиной; недопустимый переход отсутствует в списке и отклоняется API.
- [ ] Карточка без действий через 30 с получает «Не оповещено» красным и детектор `late_primary`.
- [ ] 30 с офлайн (`context.setOffline`) и повтор действия: одна запись в `status_log`.
- [ ] Всё выполнимо с клавиатуры.
- [ ] В Network только свой origin.

## Показать

Журнал с тремя карточками, полный проход одной карточки, разбор. Сравнить рядом со скриншотом
стр. 23-24: расположение блоков, названия, оранжевая полоса. Скриншоты в `docs/screenshots/wave-03/`.

## Если не получается

Раскрытие строки в журнале и постраничность можно упростить (P2). Шкала времени в разборе (P2),
но список статусов против эталона обязателен.
