# Волна 1. Датасет в базе

**Срок:** 16.09. **PRD:** разделы 8, 9.1, 10, 15.

## Цель

Классификатор, признаки, правила служб, статусы, причины отказа, типичные ошибки, 96 ситуаций из
билетов и улицы Москвы лежат в базе и отдаются через API. Всё, что дальше строится на данных,
строится на настоящих данных заказчика.

## Вход

Волна 0 закрыта. `data/organizers/` заполнена.

## Задачи

### Разбор датасета
- [ ] `docs/DATASET.md`: по каждому файлу что внутри, структура, объём, как ложится на таблицы, что не разобрано.
- [ ] Классификатор: программный разбор трёхуровневой шапки xlsx (строки 1-3), список всех колонок служб и подколонок по признакам с их кодами.
- [ ] Билеты: поворот страниц на 180°, OCR (Tesseract `rus`), таблица «№, Ситуация, Адрес» → `data/seed/tickets.json` с полем `ocr_confident`; неуверенные строки перечислены в `DATASET.md` для ручной проверки.
- [ ] Памятка: текст в `data/seed/memo.txt`, скриншоты интерфейса в `docs/reference/arm112/` (страницы 12, 13, 15, 16, 17, 23, 24) для волн 3 и 7.

### Таблицы и миграции
- [ ] Миграции для таблиц PRD раздел 10 (кроме тех, что появятся в волнах 3-10, их можно добавить позже, но лучше сразу).
- [ ] `incident_groups`, `incident_types` (три уровня, итоговый тип, ЕКП, главная служба, `service_rules`), `incident_flags`, `services` (с `no_reject` у 103 и `via_arm112`).
- [ ] `response_statuses` (включая «Добавлена», «Получена службой», `allowed_next`, `requires_comment`, `requires_order_number`), `card_statuses`, `reject_reasons`, `typical_errors` (коды из PRD 9.1 с примерами из памятки), `caller_topics`, `tickets`, `streets`.

### Импорт
- [ ] `python -m app.importers.organizers` идемпотентно загружает всё выше; печатает сводку: типов, признаков, служб, билетов.
- [ ] `resolve_services(type_code, flags)` чистая функция; табличный тест на 30 строках xlsx, включая строки с «Пострадавшие», «Нет доступа», «Угроза людям», «Правонарушение».
- [ ] Улицы Москвы с округом и районом из открытого источника (лицензия в `docs/LIBRARIES.md`); минимум все улицы из билетов.

### API справочников
- [ ] `GET /classifier/tree` (дерево кнопок опросной карты), `GET /classifier/{code}/services?flags=`, `/incident-flags`, `/services`, `/response-statuses`, `/reject-reasons`, `/caller-topics`, `/typical-errors`, `/tickets`, `/streets?q=`.
- [ ] Провайдеры `GrammarProvider` (LanguageTool) и `EmbeddingProvider` (e5-small + TF-IDF), автоматический переход на запасной при недоступности, `methods` в ответе.

## Проверка

```bash
docker compose exec backend python -m app.importers.organizers
pytest backend/tests/importers backend/tests/test_resolve_services.py -q
curl -sk https://localhost/api/classifier/tree | head -c 500
```

- [ ] Число итоговых типов равно числу строк данных в xlsx (около 1284), расхождение объяснено в `DATASET.md`.
- [ ] 96 ситуаций в `tickets.json`; неуверенных не больше 10, и они перечислены.
- [ ] `resolve_services` совпадает с колонками xlsx на всех тестовых строках.
- [ ] Статусов реагирования 9, статусов карточки 7, названия дословно из памятки.
- [ ] `/streets?q=берзар` возвращает улицу Берзарина с округом и районом.

## Показать

`docs/DATASET.md` и вывод импорта. Вадим открывает 5 случайных ситуаций из `tickets.json` и сверяет со сканом.

## Если не получается

OCR даёт мусор: распознать только первые 10 билетов, остальные пометить `ocr_confident: false` и
доразобрать руками в волне 8. Улицы: если открытый источник не тянется, взять улицы из билетов и
50 крупных улиц вручную с пометкой в `DECISIONS.md`.
