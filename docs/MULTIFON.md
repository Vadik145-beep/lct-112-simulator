# МультиФон: звонки тренажёра на обычный телефон

Дополнение к облачному голосу (`plan/track-c-vapi.md`, профиль compose `cloud`).
Браузерные звонки через Vapi Web SDK не меняются. Здесь описан путь через Asterisk:
вызов звонит на личный телефон стажёра через SIP-транк «МультиФон Бизнес».

## Что работает

| Звонок | Кто кому | Кого играет Vapi |
|---|---|---|
| Приём вызова 112 | заявитель → стажёр | заявителя |
| ДДС: звонок в службу | стажёр → дежурный | дежурного службы |
| ДДС: доклад бригады | старший группы → стажёр | старшего группы |
| ДДС: обратный звонок | стажёр → заявитель | заявителя |

- **Исходящий.** Каждый вызов звонит одновременно на софтфон, настольный телефон и личный
  телефон стажёра. Кто первым снял трубку, тот и разговаривает. На мобильном высвечивается
  номер МультиФона.
- **Входящий.** Стажёр сам звонит со своего телефона на номер МультиФона. Если ему в этот
  момент звонит вызов любого вида, звонок стажёра подхватывает его, а остальные ноги
  сбрасываются. Если ничего не звонит или номер не из таблицы, звонок отклоняется («занято»).
- **Звонки ДДС в облачном занятии** по SIP идут в Vapi: собеседника играет облако, фразы
  записываются в стенограмму этого звонка. Если облако не ответило, звонок продолжает
  локальный дежурный со своим приветствием.

## Настройка

`.env` стенда (пароль только здесь, в git его нет):

```
CLOUD_VOICE_ENABLED=true
TELEPHONY_ENABLED=true
TELEPHONY_EXTERNAL_IP=<публичный IP сервера>
MULTIFON_USER=7XXXXXXXXXX
MULTIFON_PASSWORD=...
TELEPHONY_TRAINEE_PHONES=student1=8 922 000-00-01,student2=+7 922 000-00-02
```

Запуск: `docker compose --profile cloud up -d asterisk-cloud backend`.

Телефоны стажёров меняются в «Настройки → Телефония → Телефоны стажёров (МультиФон)»,
по строке на стажёра: `логин = телефон`. Номер приводится к виду `7XXXXXXXXXX`.

На сервере должны быть открыты на вход UDP `CLOUD_SIP_PORT` (5061) и `CLOUD_RTP_START–END`
(10200–10300). Без публичного адреса звук от МегаФона не доходит: сигнализация проходит,
а RTP нет.

## Как устроено

- `deploy/asterisk-cloud/render-config.sh` пишет `generated/multifon.conf`: регистрацию на
  `multifon.ru` через `sbc.megafon.ru:5060` (МультиФон отдаёт входящие только
  зарегистрированному клиенту, `line=yes` привязывает их к эндпоинту `multifon`) и эндпоинт
  с `outbound_proxy`. Без `MULTIFON_USER` файл пустой, функция выключена.
- `extensions.conf`: контекст `trainee-targets` добавляет `PJSIP/${MOBILE}@multifon` к
  набору в `trainer-out` и `service-out`. Контекст `multifon-in` передаёт входящий в
  Stasis с аргументами `inbound,<номер звонящего>`.
- Бэкенд: `CallManager._on_inbound` ищет по номеру вызов, который звонит стажёру, и
  подменяет им ногу стажёра. Методы `CloudCallManager._service_answered_by_cloud` и
  `_service_assistant` отвечают за звонки ДДС в облаке.

## Проверено

- REGISTER логином МультиФона: `200 OK` по UDP и TCP (с ПК разработчика и из контейнера).
- Исходящий из Asterisk на 8-800-550-05-00 (справочная МегаФона): `200 OK`, параллельный набор
  `stu-/phone-/multifon` отрабатывает, X-заголовки на МультиФон не уходят.
- Звонок на собственный номер МультиФон отклоняет (`603 Decline`), поэтому петлёй
  «сам себе» входящий проверить нельзя. Нужен звонок с другого телефона.
- pytest: `tests/telephony/test_multifon.py` (нормализация номеров, набор с `MOBILE`,
  подхват входящим для 112 и ДДС, отказ неизвестному номеру, звонок ДДС в Vapi и запасной
  путь).
