# Голосовые тесты с облачным заявителем (Vapi)

Набор `frontend/e2e/vapi/` — двенадцать живых звонков против стенда с включённым режимом
«Облачный голос» (`CLOUD_VOICE_ENABLED=true`, ключи Vapi). В каждом звонке заявителя целиком
играет Vapi (распознавание → модель → голос ElevenLabs), а диспетчера — тест: вместо микрофона
Chrome получает синтетический поток, в который подмешиваются заранее озвученные реплики
(`phrases/*.wav`, голос Windows «Irina»). Vapi слышит живую речь, отвечает голосом, стенограмма
приходит на бэкенд вебхуками. После каждой реплики тест ждёт ответ заявителя в стенограмме,
затем заполняет карточку, завершает звонок, сохраняет и открывает разбор.

Смысл набора — не «звонок проходит», а **подсчёт баллов**: после каждого звонка оценка из API
сверяется с независимым пересчётом (`lib/scoring.ts` — порт формул движка
`backend/app/domain/evaluation/`): нормировка весов к 100, каждая составляющая по её `items`
(адрес по весам частей, службы по Жаккару, время по нормативу, грамотность по числу
замечаний, штрафы типичных ошибок), обязательные темы по ключевым словам из стенограммы,
итог = Σ баллов / Σ максимумов × 100, зачёт по порогу, совпадение балла на карточке,
в разборе и в API. Двенадцать случаев подобраны так, чтобы задеть каждую ветку правил
(частичные баллы, нормировка нестандартных весов, порог зачёта, линейный спад времени,
пустой ввод, лишние признаки).

Арифметика верна, но прогон показал две дыры в *правилах* (закрыты в #69 и #70, после них
ожидания тестов 06, 08 и 11 меняются на «незачёт»): молчащий диспетчер получал зачёт с 91

карточка получала 45, потому что грамотность, время и признаки давали максимум за отсутствие
ввода. Ещё три наблюдения, учтённые в тестах: движок намеренно не пишет темы «повторите» /
«вне темы» в ходы; признак «Пострадавшие» сам добавляет службы по правилам классификатора
(ПСЦ, 103); заявитель Vapi после «до свидания» кладёт трубку не всегда.

Задержка ответа заявителя по 127 ходам двенадцати звонков (от конца фразы диспетчера до
первого звука ответа, `latency_ms` в ходе): медиана **0,46 с**, p90 1,24 с, максимум 1,9 с
(подробнее в [PERFORMANCE.md](PERFORMANCE.md)).

## Как запустить

Нужен стенд с облачным голосом и учётные записи преподавателя и обучающегося на нём
(обучающийся должен состоять в группе преподавателя; тест завершает другие идущие занятия
«Приём вызова», иначе софтфон берёт чужой звонок). Учётные данные только через окружение:

```bash
cd frontend
E2E_BASE_URL=https://<стенд> \
E2E_TEACHER_LOGIN=… E2E_TEACHER_PASSWORD=… \
E2E_STUDENT_LOGIN=… E2E_STUDENT_PASSWORD=… \
npx playwright test e2e/vapi
```

Около 40 минут на все двенадцать звонков (каждый — отдельное занятие, ~3 минуты и кредиты
Vapi). `E2E_CASES=04,05` — выборочно, `E2E_HEADLESS=1` — без окна браузера. Без переменных
учётных записей набор пропускается, так что обычный `npm run e2e` его не гоняет. Результаты в
`frontend/e2e/vapi/out/` (не в git): `suite-<час>.md` — строка на тест, `<час>-<тест>.json` —
стенограмма, оценка и все проверки, `<час>-<тест>.png` — экран после сохранения.

Файлы: `vapi-suite.spec.ts` — двенадцать случаев и ожидания; `lib/flow.ts` — занятие по API,
вход, звонок, реплики, варианты карточки; `lib/scoring.ts` — независимый пересчёт;
`lib/audio-bridge.js` — подмена `getUserMedia` синтетическим микрофоном; `phrases/` — реплики
диспетчера и `make-phrases.ps1` для их пересоздания (Windows, голос «Microsoft Irina»).
