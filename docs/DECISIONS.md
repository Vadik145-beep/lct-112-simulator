# Решения

Самостоятельные решения по неясным местам, одной-двумя строками. Предложения по изменению PRD
и плана тоже сюда.

## Волна 0

- Папка миграций называется `backend/migrations/`, а не `alembic/`: одноимённый пакет рядом с
  кодом перекрывал бы библиотеку `alembic`.
- Роль БД приложения (`APP_DB_USER`) создаётся скриптом инициализации PostgreSQL; права на
  таблицы выдают миграции через `migrations/grants.py`. На `audit_log` у роли только SELECT и
  INSERT. Вставки в аудит сериализуются `pg_advisory_xact_lock`, чтобы цепочка хэшей не ветвилась.
- Refresh-токен — JWT в httpOnly-cookie с `path=/api/auth`; отзыв через `users.token_version`
  (смена пароля увеличивает версию, старые токены перестают работать). Хранилища сессий нет.
- Блокировка входа: 423 Locked с временем окончания в тексте; неизвестный логин и неверный
  пароль дают одинаковый ответ 401, чтобы не раскрывать список логинов.
- `must_change_password`: пользователь может войти, вызвать `/me` и `/auth/change-password`,
  остальные эндпоинты отвечают 403 `password_change_required`. Сид ставит флаг только при
  `DEMO_MODE=false`.
- `POST /auth/demo/{role}` при `DEMO_MODE=false` отвечает 404, как будто эндпоинта нет.
- Публичный `GET /api/config` (demo_mode, external_ai, app_env) — фронтенду нужно знать,
  показывать ли демо-кнопки.
- PostgreSQL и Redis публикуют порты на хост (`POSTGRES_PORT`, `REDIS_PORT`) — для pytest с хоста.
  Тесты используют отдельную базу `trainer_test`, создают её сами.
- Каркас кабинетов отдаёт `GET /api/{role}/cabinet` с проверкой роли на бэкенде: так фронтенд и
  тесты проверяют 403 уже в волне 0.
- Сертификаты TLS генерируются при первом старте контейнера nginx в volume `certs`
  (тот же `deploy/certs/generate.sh` можно запустить руками).
- Проверка грамотности (LanguageTool) поднята в compose, но до волны 1 не используется.
- Python в контейнере 3.12 по PRD; локально допустим 3.13 (`requires-python >= 3.12`).
- Vitest обновлён до 3.x: версия 2.x тянет Vite 5 и конфликтует с Vite 6 по типам.
- Playwright подключён уже в волне 0 (`frontend/e2e/wave-00.spec.ts`, `npm run e2e`): раздел
  «Показать» проходится браузером автоматически, скриншоты пишутся в `docs/screenshots/wave-00/`.
  `scripts/check.sh` запускает e2e, только если стенд отвечает на `/health`.
- Экран входа возвращает «туда, откуда пришёл» только внутри кабинета своей роли; иначе в свой
  кабинет. Пока восстанавливается прошлая сессия, форма входа не показывается (иначе гонка:
  запоздалое восстановление перезаписывало только что выполненный вход).
- Маркер `has_session` в localStorage: `/auth/refresh` вызывается только если сессия на этом
  браузере уже была, чтобы при первом визите в консоли не было 401.
