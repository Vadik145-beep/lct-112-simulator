# Замеры диалога с заявителем

Дата: 16.09.2026 17:54. Машина: ноутбук разработки, Docker Desktop под Windows: 4 потока на сервер модели, 8 ГБ на Docker. Скрипт: `scripts/bench_dialog_latency.py`.

Серия из 20 вопросов оператора (по 4 на каждый из 5 сценариев приёма вызова) текстом
и голосом.
Голос вопросов: Piper, голос ru_female_1 (не используется сценариями серии).
Задержка считается от отправки вопроса до готового
текста ответа заявителя (для голоса включая распознавание). Судья ответов «не по теме»:
http://localhost:8083.

Оговорки:

- Судья «не по теме» — 3B, а не 7B по плану: в Docker Desktop на машине разработки 8 ГБ и два соседних стека, 7B не помещается. Судья слабый (7 из 20 ответов режима buttons назвал «не по теме»), колонку читать как грубую оценку; прогон с 7B — на стенде.
- Серия шла второй раз на тех же серверах: системные промпты сценариев уже были в кеше слотов. Холодный первый вопрос нового сценария на 1.5B — около 10 с (обработка промпта ~700 токенов на 4 потоках), дальше по кешу ~1 с; на первом прогоне p90 select текстом был 10,3 с.
- Голос вопросов синтезирован Piper, а не записан человеком: «распознано верно» 11/20 говорит о связке Piper→Whisper base, а не о речи оператора; с настоящими записями (--voice-dir) перемерить на стенде.
- Точность 3B ниже, чем у 1.5B, и лицензия 3B некоммерческая (Qwen Research License), поэтому 3B не кандидат для стенда.
- Раздел точности перемерен после правки ключевых слов (целое слово «дом»); задержки и провокации — из полного прогона выше.
