# Установка, настройка и восстановление

Документ описывает установку на сервер с интернетом и в закрытом контуре без интернета, первый
вход, настройки, телефонию, облачные режимы, резервное копирование, восстановление и обновление.
Все команды вводятся в терминале сервера в папке установки.

## 1. Требования

**Сервер:**

- процессор от 6 ядер (Intel Core i7, Xeon или аналог), видеокарта не нужна;
- оперативная память от 16 ГБ, рекомендуется 32 ГБ (минимум по техническому заданию);
- диск SSD, свободно от 100 ГБ: программа с моделями занимает около 40 ГБ, остальное — база,
  записи разговоров и резервные копии; техническое задание рекомендует NVMe от 512 ГБ;
- Linux: Ubuntu 22.04 или 24.04;
- Docker Engine и docker compose версии 2.

Скрипты установки (`start.sh`, `install.sh`) рассчитаны на Linux. На Windows и macOS они не
запускаются; систему можно поднять вручную через Docker Desktop для разработки и показа, но как
сервер учебного класса этот вариант не проверялся.

Без моделей искусственного интеллекта (профиль `ai` выключен) система работает и на машине
с 8 ГБ памяти: собеседники отвечают по ключевым словам заранее записанными репликами, речь
обучающегося не распознаётся, он пишет текстом.

**Рабочие места:** браузер Chrome, Яндекс.Браузер или Firefox, гарнитура с микрофоном. Ставить на
рабочие места ничего не нужно. Настольный IP-телефон подключается дополнительно (раздел 7).

**Сеть:** рабочие места должны видеть сервер по HTTPS (порт 443; порт 80 только перенаправляет на
443). Для телефонии дополнительно открываются порт SIP (5060, UDP и TCP) и диапазон голосовых
портов (по умолчанию 10000–10100, UDP). Служебные порты (база, Redis, модели, распознавание,
управление телефонией) по умолчанию слушают только сам сервер (`INTERNAL_BIND=127.0.0.1`) и
снаружи не видны.

## 2. Сервер с интернетом

```bash
git clone https://github.com/Vadik145-beep/lct-112-simulator.git
cd lct-112-simulator
./start.sh                      # или ./start.sh --host 192.168.1.50
```

Что делает `start.sh`:

1. Проверяет, что Docker установлен, запущен и есть docker compose v2.
2. Скачивает модели (около 9 ГБ) одним архивом с Google Диска команды и сверяет контрольную
   сумму. Если связь оборвалась, повторный запуск докачивает с того же места. Если архив
   недоступен или повреждён, модели скачиваются по одной с официальных источников
   (`scripts/fetch_models.sh`: Hugging Face и models.silero.ai). Если модели уже на месте, шаг
   пропускается.
3. Если файла `.env` ещё нет, создаёт его из `.env.example` с настройками демонстрационного
   стенда: свой случайный `SECRET_KEY`, адрес сервера в сертификате (`TLS_HOSTS`) и в телефонии
   (`TELEPHONY_EXTERNAL_IP`), `APP_ENV=production`, модель собеседников Qwen2.5-3B с контекстом
   16384, написание карточек той же моделью (`LLM_GEN_URL=http://llm-dialog:8080`),
   распознавание `faster-whisper-small`, телефония включена, логины и вход в один клик на
   странице входа (`QUICK_LOGIN=true`, `SHOW_DEMO_CREDENTIALS=true`). Уже существующий `.env`
   скрипт не трогает.
4. Собирает и запускает систему с профилями `ai` и `telephony`; отдельный сервер модели 7B
   (`llm-gen`) не запускается (`--scale llm-gen=0`), его работу делает модель собеседников.
5. Ждёт, пока сервер приложения станет «healthy», и печатает адрес, логины и пароль.

Адрес сервера скрипт определяет сам (`hostname -I`); если у сервера несколько адресов, укажите
нужный через `--host`. Первый запуск занимает от 30 минут до часа (скачивание моделей и сборка
образов), повторный — несколько минут.

**Без `start.sh`** (свои настройки с самого начала):

```bash
cp .env.example .env            # поменять SECRET_KEY, пароли и остальное (раздел 5)
./scripts/fetch_models.sh       # модели, около 9 ГБ
docker compose --profile ai --profile telephony up -d --build
```

Значения по умолчанию в `.env.example` отличаются от стенда: модель собеседников Qwen2.5-1.5B,
карточки пишет отдельный сервер с моделью Qwen2.5-7B (`llm-gen`), распознавание
`faster-whisper-base`, телефония выключена, логины на странице входа не показываются.

## 3. Сервер без интернета (закрытый контур)

Сборка образов требует интернета (пакеты Python и npm, базовые образы), поэтому поставка
собирается на машине с интернетом и переносится в контур готовой. В контуре ничего не скачивается
и не собирается.

**На машине с интернетом** (Linux, Docker, Git, около 25 ГБ свободного места):

```bash
git clone https://github.com/Vadik145-beep/lct-112-simulator.git
cd lct-112-simulator
./scripts/fetch_models.sh                       # или models.tar с Google Диска, как в start.sh
./scripts/offline_bundle.sh --with-models       # результат — папка ./offline-bundle (около 11 ГБ)
```

Что попадает в поставку:

| Файл | Что внутри |
|---|---|
| `images.tar` | все образы всех профилей (`ai`, `telephony`, `cloud`), собранные и скачанные на этой машине |
| `source.tar` | исходники репозитория без истории git |
| `models.tar` | папка моделей (только с `--with-models`) |
| `organizers.tar` | материалы заказчика из `data/organizers`, если папка есть |
| `install.sh` | установщик |
| `SHA256SUMS`, `VERSION` | контрольные суммы и версия сборки |

Без `--with-models` поставка занимает около 2 ГБ и ставится без профиля `ai` (раздел 1, работа без
моделей). Другая папка вывода задаётся `--out`.

**На сервере в контуре** нужны только Docker Engine и docker compose v2. Их ставят заранее из
пакетов дистрибутива: в поставку Docker не входит. Папка `offline-bundle` переносится на сервер
флешкой, диском или по локальной сети.

```bash
cd offline-bundle
sudo ./install.sh                                   # в /opt/lct/app, как на стенде
sudo ./install.sh --dir /srv/trainer --host 10.0.0.5
sudo ./install.sh --profile telephony               # только выбранные профили
```

Установщик:

1. проверяет контрольные суммы всех файлов поставки;
2. загружает образы (`docker load`);
3. распаковывает исходники, материалы заказчика и модели в папку установки (по умолчанию
   `/opt/lct/app`);
4. если `.env` ещё нет, создаёт его так же, как `start.sh` (раздел 2, пункт 3); телефония
   включается, только если поднимается профиль `telephony`;
5. поднимает систему с `--pull never --no-build`: любая попытка что-то скачать завершилась бы
   ошибкой, а не тихим обращением в сеть. Без `--profile` поднимаются `ai` (если в поставке есть
   модели) и `telephony`;
6. ждёт готовности и печатает адрес, логины и пароль.

При первом запуске сервер приложения сам применяет миграции базы, загружает классификатор,
памятку, учебные билеты и справочник улиц, создаёт пользователей и раскладывает записи голосов.

Образы собранных сервисов имеют постоянные имена (`lct112/backend`, `lct112/nginx`,
`lct112/backup`, `lct112/stt`, `lct112/asterisk`, `lct112/asterisk-cloud`; тег `APP_VERSION`, по
умолчанию `latest`), поэтому установка не зависит от имени папки.

Проверено 22.09.2026: поставка без моделей (1,8 ГБ образов) развёрнута в чистую папку на сервере
с удалёнными образами и `--pull never`; журнал Docker за время установки не содержит ни одного
обращения к реестру; `/health` отвечает ok, страница входа открывается, сквозной тест «полный
проход» ДДС проходит. Установка поставки с моделями на чистую машину без сети целиком не
прогонялась.

## 4. Первый вход и проверка

Откройте адрес, который напечатал скрипт, например `https://192.168.1.50`. Браузер предупредит
о сертификате: у системы свой центр сертификации. Нажмите «Дополнительные» → «Перейти на сайт».
Чтобы предупреждения не было, установите на рабочие места корневой сертификат:

```bash
docker compose cp nginx:/etc/nginx/certs/ca.crt .
```

Сертификат выпускается при первом запуске на адреса из `TLS_HOSTS` и действует 825 дней. Если
адрес сервера сменился, поправьте `TLS_HOSTS` и выпустите сертификат заново (корневой
сертификат при этом не меняется):

```bash
docker compose exec nginx rm /etc/nginx/certs/server.crt /etc/nginx/certs/server.key
docker compose restart nginx
```

**Пользователи после установки** (`DEMO_MODE=false`):

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `112112112` |
| Преподаватель | `teacher` | `112112112` |
| Обучающийся | `student` | `112112112` |
| Обучающийся | `student2` | `112112112` |

Пароль задаётся настройкой `SEED_PASSWORD` и действует только при первом запуске: пользователи
создаются один раз, и смена `SEED_PASSWORD` потом их пароли не меняет. Менять пароль при первом
входе не требуется. Обучающимся назначена служба «Гор. хозяйство» (ЕДЦ ЖКХ). Групп и занятий
после установки нет: их создаёт преподаватель. Режим оператора 112 у преподавателя и обучающихся
скрыт, администратор включает его отдельным пользователям галочкой «Режим 112».

Скрипты установки включают на странице входа таблицу логинов с паролем и кнопки «Войти» в один
клик, как на демонстрационном стенде. Пока таблица включена, показанные в ней пароли сменить
нельзя. На рабочем сервере выключите оба параметра и перезапустите систему (раздел 5), затем
смените пароли в разделе администратора «Пользователи»:

```
QUICK_LOGIN=false
SHOW_DEMO_CREDENTIALS=false
```

`DEMO_MODE=true` (до первого запуска) вместо этого создаёт демонстрационный набор: `teacher1`,
`teacher2`, `student1` … `student12`, две группы и демо-занятия. Если строки `DEMO_MODE` в `.env`
нет совсем, docker compose подставит `true`, поэтому строку не удаляйте.

**Проверка после установки:**

1. `https://<адрес>/health` отвечает `"status":"ok"`.
2. `docker compose ps` — все сервисы `running` или `healthy`.
3. Администратор → «Состояние»: все плитки сервисов «работает».
4. Преподаватель создаёт группу, добавляет в неё `student` и создаёт занятие.
5. Обучающийся в «Моих заданиях» нажимает «Открыть журнал АРМ-112» — в журнале первая карточка.

## 5. Настройки

Почти всё задаётся в файле `.env` в папке установки; образец с пояснениями — `.env.example`.
После правки систему перезапускают той же командой, что и запускали, например:

```bash
docker compose --profile ai --profile telephony up -d --scale llm-gen=0
```

Часть настроек администратор меняет в интерфейсе, в разделе «Настройки»: ожидание ответа на
вызов, запись разговоров, телефоны стажёров, расписание и число копий, порог «Не завершено»,
уровень журнала. Изменения записываются в журнал аудита.

### 5.1. Общие и безопасность

| Настройка | Что задаёт |
|---|---|
| `SECRET_KEY` | Секрет для подписи входа, не короче 32 символов. Скрипты установки генерируют свой; вручную: `openssl rand -hex 32` |
| `POSTGRES_PASSWORD`, `APP_DB_PASSWORD` | Пароли владельца базы и роли приложения. Поменять **до первого запуска**: потом они уже записаны в базу. Вместе с ними поправить пароли в `DATABASE_URL` и `DATABASE_ADMIN_URL` |
| `SEED_PASSWORD` | Пароль пользователей, создаваемых при первом запуске, по умолчанию `112112112` |
| `APP_ENV` | `production` для рабочей установки (без подробных ошибок) |
| `DEMO_MODE` | Демонстрационный набор пользователей и занятий, по умолчанию `false` |
| `QUICK_LOGIN`, `SHOW_DEMO_CREDENTIALS` | Кнопки «Войти» без пароля и таблица логинов на странице входа. На рабочем сервере `false` |
| `ALLOW_EXTERNAL_AI` | Разрешить внешние ИИ-сервисы (раздел 8). В закрытом контуре `false` |
| `TLS_HOSTS` | Адреса и имена сервера для сертификата, через запятую |
| `HTTP_PORT`, `HTTPS_PORT` | Порты веб-интерфейса, по умолчанию 80 и 443 |
| `INTERNAL_BIND` | На каком адресе слушают служебные порты. `127.0.0.1` — только сам сервер |
| `ACCESS_TOKEN_MINUTES`, `REFRESH_TOKEN_DAYS` | Время жизни входа: 15 минут с автоматическим продлением до 7 дней |
| `LOGIN_MAX_ATTEMPTS`, `LOGIN_LOCK_MINUTES` | Блокировка входа после неудачных попыток: 5 попыток, 15 минут |
| `TZ` | Часовой пояс интерфейса и отчётов, по умолчанию `Europe/Moscow` |
| `LOG_LEVEL` | Уровень журнала сервера, по умолчанию `INFO` |
| `BACKUP_TIME`, `BACKUP_KEEP` | Время ежедневной копии (03:00) и сколько копий хранить (14) |

### 5.2. Модели ИИ

| Настройка | Что задаёт |
|---|---|
| `LLM_DIALOG_MODEL` | Модель собеседников: `qwen2.5-1.5b-…` (по умолчанию) или `qwen2.5-3b-…` (стенд, скрипты установки) |
| `LLM_DIALOG_CTX`, `LLM_DIALOG_SLOTS` | Контекст и число одновременных разговоров сервера модели: 8192 и 4. Если карточки пишет модель собеседников, нужен контекст 16384 |
| `LLM_GEN_URL` | Кто пишет карточки и сценарии: `http://llm-gen:8080` (отдельная 7B), `http://llm-dialog:8080` (модель собеседников) или облачная модель (раздел 8) |
| `LLM_GEN_MODEL`, `LLM_GEN_CTX` | Модель и контекст отдельного сервера генерации |
| `LLM_GEN_TIMEOUT_SECONDS` | Сколько ждать сценарий от модели в библиотеке преподавателя, по умолчанию 900 с |
| `DIALOG_MODE` | Режим разговора по умолчанию: `select` — модель выбирает утверждённую реплику |
| `STT_MODEL` | Распознавание речи: `faster-whisper-base` быстрее, `faster-whisper-small` точнее |
| `TTS_PROVIDER` | Голос собеседников для фраз без готовой записи: `auto` — Silero, без него Piper, без голосов — только текст |
| `LLM_THREADS` | Сколько ядер процессора отдать каждому серверу модели и распознаванию, по умолчанию 4 |
| `LLM_LOAD_MODE` | `auto` на Linux; `mlock` на Docker Desktop под Windows |
| `MODELS_DIR` | Папка с моделями на сервере, по умолчанию `./models` |

## 6. Модели искусственного интеллекта

Модели скачиваются один раз: `start.sh` делает это сам, вручную — `./scripts/fetch_models.sh`.
Скрипт сверяет размер и контрольную сумму каждого файла и докачивает оборванные; отдельную часть
можно скачать ключом `--only llm|stt|tts|embeddings`. Перечень файлов — в
`scripts/models.manifest`, лицензии — в `docs/LIBRARIES.md`.

| Что | Файлы | Для чего |
|---|---|---|
| Qwen2.5-1.5B, Qwen2.5-3B, Qwen2.5-7B (GGUF Q4_K_M) | `models/llm` | собеседники по телефону, написание карточек и сценариев |
| faster-whisper base и small | `models/stt` | распознавание речи обучающегося |
| Silero TTS v4, Piper (три голоса) | `models/tts` | голос собеседников для фраз без готовой записи |
| multilingual-e5-small | `models/embeddings` | смысловое сравнение ответов с эталоном при оценке |
| Silero VAD | `models/vad` | границы фраз в телефонном звонке |

Голос Silero скачивается с models.silero.ai. Если этот адрес закрыт, скачайте файл на другой
машине и положите в `models/tts/silero_v4_ru.pt`.

Фразы учебных сценариев, дежурных служб и бригады из поставки уже озвучены заранее и
поставляются записями вместе с данными; синтез на сервере нужен только для новых и изменённых
фраз и для режима свободной генерации.

Лицензии: Qwen2.5-3B и Silero TTS распространяются по некоммерческим лицензиям. Для учебного
контура заказчика это допустимо; при коммерческом использовании модель собеседников меняется на
1.5B или 7B (`LLM_DIALOG_MODEL`), голос — на Piper (`TTS_PROVIDER=piper`).

## 7. Телефония

По умолчанию все разговоры занятия идут в браузере: обучающийся говорит в гарнитуру, речь
распознаётся на сервере, собеседник отвечает голосом в браузере. Для этого телефония не нужна.

Телефония (Asterisk, профиль `telephony`) нужна для занятий с галочкой «Живой звонок на телефон»:
вызовы такого занятия звонят одновременно в софтфон браузера, на настольный IP-телефон
обучающегося и на мобильный через линию оператора связи. Галочка видна в форме занятия в режиме
оператора 112 с облачным голосом (раздел 8.2), когда включены телефония и линия оператора связи
(транк ниже или МультиФон облачного контура).

```bash
docker compose --profile telephony up -d
```

В `.env` задать `TELEPHONY_ENABLED=true`, внешний адрес сервера `TELEPHONY_EXTERNAL_IP` (без него
звук не пойдёт в одну сторону), диапазон голосовых портов `TELEPHONY_RTP_START` и
`TELEPHONY_RTP_END`, порт SIP `SIP_PORT`, пароль управления `ARI_PASSWORD`. Скрипты установки
включают телефонию и подставляют адрес сервера сами; без линии оператора связи она просто не
используется.

На межсетевом экране открыть порт SIP (по умолчанию 5060, UDP и TCP) и диапазон голосовых портов
(UDP).

**Софтфон в браузере** настраивается автоматически: учётная запись создаётся вместе с
пользователем, данные приходят при входе.

**Настольный IP-телефон** (например, РТУ Т16Р): в настройках аппарата указать адрес сервера,
логин и пароль из кабинета администратора (меню «⋯» у обучающегося → «SIP-учётка»), кодеки G.722
и PCMA, регистрация по UDP или TCP. Шифрование SIP (TLS, SRTP) не поддерживается.

Если телефония выключена (`TELEPHONY_ENABLED=false`), занятия работают полностью, кроме живого
звонка на телефон.

### Внешний SIP-транк оператора связи (необязательно)

Транк подключают, чтобы вызовы занятия звонили на настоящие телефоны и чтобы обучающийся мог сам
позвонить на номер линии. Подробности — `docs/TRUNK.md`.

В `.env` задать данные учётной записи оператора связи:

```
TELEPHONY_TRUNK_USER=       # номер или логин у оператора
TELEPHONY_TRUNK_PASSWORD=   # пароль SIP
TELEPHONY_TRUNK_DOMAIN=     # домен регистрации, например multifon.ru
TELEPHONY_TRUNK_PROXY=      # узел оператора, например sbc.megafon.ru:5060
TELEPHONY_TRUNK_CODECS=alaw,ulaw
TELEPHONY_TRUNK_INBOUND=    # логин обучающегося, которому идут все входящие; пусто = входящие разбирает сервер
```

Перезапустить телефонию и сервер приложения:
`docker compose --profile telephony up -d --force-recreate asterisk backend`.

Проверка: `docker compose exec asterisk asterisk -rx "pjsip show registrations"` должна показать
состояние `Registered`. Номер обучающегося для звонков задаётся в форме занятия, в профиле
обучающегося или администратором в «Настройки → Телефония» строками `логин = телефон`.

Если поля пустые, транк не создаётся. Ограничения оператора учитывать отдельно: у «МультиФон
Бизнес» МегаФона не больше трёх одновременных регистраций на учётную запись и голосовые порты
10000–27999 на стороне оператора.

## 8. Облачные режимы (только вне закрытого контура)

По умолчанию облачные режимы выключены, а все ключи в `.env.example` пустые: система не обращается
в интернет. Облако включается только явно, на сервере с интернетом, своими ключами. Если внешний
адрес модели или облачный голос указаны без `ALLOW_EXTERNAL_AI=true`, сервер приложения не
запустится и напишет в журнале, какая настройка внешняя.

### 8.1. Облачная модель для карточек

Карточки режима «Задания формирует ИИ» и сценарии в библиотеке может писать облачная модель с
API, совместимым с OpenAI. Облачная модель пишет карточку за несколько секунд, локальная на
процессоре — около минуты (раздел «Производительность»).

```
ALLOW_EXTERNAL_AI=true
LLM_GEN_URL=https://<адрес API без /v1>
LLM_GEN_API_KEY=<ключ сервиса>
LLM_GEN_API_MODEL=<имя модели у сервиса>
```

Ключ без имени модели — ошибка запуска. Если облачная модель не ответила за 30 секунд (локальная —
за 120), карточку собирает шаблон, и занятие не останавливается.

### 8.2. Облачный голос (Vapi)

В занятии с режимом «Свободная генерация речи (с интернетом)» собеседников играет облачный сервис
Vapi: распознавание речи, языковая модель и голос ElevenLabs. Разговор идёт из браузера
обучающегося; с живым звонком на телефон — через отдельный Asterisk облачного контура.

Что нужно:

- сервер с интернетом и доменным именем, которое видно из интернета (Vapi присылает события
  разговора на адрес сервера);
- сертификат Let's Encrypt для этого имени;
- аккаунт Vapi с приватным и публичным ключом (Integrations → API keys).

Настройки в `.env`:

```
ALLOW_EXTERNAL_AI=true
CLOUD_VOICE_ENABLED=true
VAPI_API_KEY=<приватный ключ>
VAPI_PUBLIC_KEY=<публичный ключ>
PUBLIC_HOST=<доменное имя сервера>
CLOUD_VOICE_PUBLIC_URL=https://<доменное имя сервера>
```

Сертификат выпускается проверкой через порт 80: nginx отдаёт папку проверок из тома
`certbot-www` и подключает сертификат из тома `letsencrypt`. Имена томов начинаются с имени
проекта compose (`docker volume ls`), например:

```bash
docker run --rm -v <проект>_certbot-www:/var/www/certbot -v <проект>_letsencrypt:/etc/letsencrypt \
  certbot/certbot certonly --webroot -w /var/www/certbot -d <доменное имя> --agree-tos -m <почта>
docker compose up -d --force-recreate nginx backend
```

При `CLOUD_VOICE_ENABLED=true` nginx сам добавляет адреса Vapi и Daily в политику безопасности
страницы. Модель, голос и распознавание внутри Vapi задаются `CLOUD_VOICE_MODEL`,
`CLOUD_VOICE_VOICE_ID…`, `CLOUD_VOICE_TRANSCRIBER_…` (значения по умолчанию — в `.env.example`).
Если облако не ответило за `CLOUD_VOICE_ANSWER_SECONDS` (15 с) или звонок из браузера не
поднялся, разговор продолжается локально, текстом и микрофоном.

**МультиФон облачного контура.** Чтобы облачные звонки шли и на мобильные телефоны стажёров,
вместо профиля `telephony` поднимают профиль `cloud` (два профиля вместе не поднимать) и задают
`MULTIFON_USER`, `MULTIFON_PASSWORD`; на вход открываются UDP `CLOUD_SIP_PORT` (5061) и
`CLOUD_RTP_START`–`CLOUD_RTP_END` (10200–10300). Подробности — `docs/MULTIFON.md`.

## 9. Резервное копирование и восстановление

Сервис `backup` каждый день в `BACKUP_TIME` делает копию базы (`pg_dump`, файл
`trainer-ГГГГММДД-ЧЧММСС.dump` в томе `backups`) и хранит последние `BACKUP_KEEP` копий, более
старые удаляет. Копию можно сделать вручную в кабинете администратора («Копии» → «Сделать копию
сейчас»), там же меняется расписание: служба подхватывает его в течение минуты.

Копия содержит базу: пользователей, занятия, результаты, сценарии, журнал аудита. Записи
разговоров, озвученные реплики и загруженные методические материалы лежат в томе `storage` и в
копию базы не входят. Обе части хранятся на том же сервере; чтобы пережить отказ диска, их
копируют на другой носитель:

```bash
docker compose cp backup:/backups ./backups-copy
docker compose cp backend:/storage ./storage-copy
```

**Проверка восстановления** (рабочая база не меняется):

```bash
./scripts/restore_test.sh
```

Скрипт делает свежую копию, разворачивает её в отдельную базу `trainer_restore_test`, проверяет
вход администратора кодом приложения и удаляет проверочную базу.

**Восстановление из копии:**

```bash
docker compose stop backend worker
docker compose exec -T backup pg_restore --clean --if-exists --no-owner -d trainer /backups/<имя файла>.dump
docker compose cp ./storage-copy/. backend:/storage      # если восстанавливаются и записи
docker compose start backend worker
```

`trainer` — имя базы из `POSTGRES_DB`. Чтобы восстановить на новом сервере, сначала установите
систему (раздел 2 или 3), затем положите файл копии в том:
`docker compose cp <имя файла>.dump backup:/backups/` и выполните команды выше.

## 10. Обновление

Перед обновлением сделайте копию (раздел 9).

**С интернетом:**

```bash
git pull
./start.sh
```

`start.sh` не скачивает модели повторно и не трогает существующий `.env`, а только пересобирает и
перезапускает систему.

**Без интернета:** соберите новую поставку (раздел 3) и запустите `install.sh` с той же папкой
установки. Он заменит исходники и образы, а `.env`, база, записи и копии останутся.

Миграции базы применяются автоматически при старте сервера приложения.

Если обновление сменило голосовой движок, уже озвученные синтезом реплики остаются в старом
голосе. Переозвучить их текущим движком:

```bash
docker compose exec worker python -m app.scripts.revoice --dry-run   # сколько реплик
docker compose exec worker python -m app.scripts.revoice
```

Заранее записанные фразы из поставки и записи, загруженные преподавателем, команда не трогает.

## 11. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `docker: command not found` или `permission denied` | Нет Docker или прав: установить Docker, запускать через `sudo` |
| `port is already allocated` | Порт 80 или 443 занят. В `.env` поставить `HTTP_PORT=8080`, `HTTPS_PORT=8443`, запустить снова, открывать адрес с `:8443` |
| Первый запуск завершился `dependency failed to start` | На медленной машине база создаётся дольше проверки готовности. Запустить ту же команду ещё раз |
| Страница не открывается сразу после запуска | Модели ещё загружаются: подождать 2–3 минуты |
| Браузер предупреждает о сертификате | Установить корневой сертификат (раздел 4) |
| Сервер приложения не стартует, в журнале «Внешний адрес ИИ-сервиса при ALLOW_EXTERNAL_AI=false» | Указан внешний адрес модели или включён облачный голос без разрешения. Вернуть локальный адрес или включить `ALLOW_EXTERNAL_AI=true` (только вне закрытого контура) |
| Собеседник отвечает невпопад или по ключевым словам | Не поднят профиль `ai`, модель не скачана или перегружена; в «Состоянии» проверить плитку «Модель диалога». Распознавание путает слова — `STT_MODEL=faster-whisper-small` |
| Собеседник не слышит обучающегося | Браузеру не дан доступ к микрофону: разрешить в адресной строке, проверить гарнитуру |
| Карточки ИИ однотипные или приходят через две минуты | Модель не успела, карточку собрал шаблон. Проверить плитку модели генерации; на процессоре это ожидаемо (раздел 8.1) |
| Всё медленно, модель перезапускается сама | Мало памяти: нужно от 16 ГБ. Не запускать рядом другие программы, уменьшить `LLM_THREADS` или перейти на `STT_MODEL=faster-whisper-base` и модель 1.5B |
| В оценке «грамотность не проверена» | Не отвечает LanguageTool: `docker compose restart languagetool`; остальная оценка работает |
| Настольный телефон не звонит | Телефон звонит только в занятиях с живым звонком (раздел 7). Проверить `TELEPHONY_ENABLED=true`, профиль `telephony`, порт SIP и голосовые порты |
| В «Копиях» служба копий не отвечает | `docker compose up -d backup` |
| В «Состоянии» плитка «не отвечает» | `docker compose ps` покажет, какой сервис остановлен; `docker compose up -d` с теми же профилями поднимет его |

Журнал сервиса: `docker compose logs --tail 100 backend`.
