# Установка и эксплуатация

Документ описывает установку в закрытом контуре, перенос без интернета, настройку телефонии,
резервное копирование и восстановление.

## 1. Требования

**Сервер приложения** (минимум по техническому заданию):

- процессор от 6 ядер (Intel Core i7, Xeon или аналог);
- оперативная память от 32 ГБ;
- накопитель NVMe SSD от 512 ГБ;
- операционная система Ubuntu 20.04 и новее либо Windows 10/11;
- Docker и Docker Compose.

Без моделей искусственного интеллекта (профиль `ai` выключен) система работает и на машине с 8 ГБ
памяти: заявитель в этом режиме отвечает заранее утверждёнными репликами.

**Рабочее место обучающегося:** браузер Chrome, Firefox или Яндекс.Браузер, гарнитура с
микрофоном. Настольный IP-телефон подключается дополнительно.

## 2. Обычная установка

```bash
git clone <адрес репозитория> lct-112-simulator
cd lct-112-simulator
cp .env.example .env
```

В файле `.env` обязательно поменять `SECRET_KEY`, `POSTGRES_PASSWORD`, `APP_DB_PASSWORD`,
`SEED_PASSWORD`, `ARI_PASSWORD`. Для боевой установки поставить `DEMO_MODE=false`: тогда при первом
запуске создаётся только администратор, а демонстрационные пользователи и история не создаются.

```bash
docker compose up -d --build
curl -sk https://localhost/health
```

Интерфейс открывается по адресу `https://localhost`. Сертификат выпускает внутренний центр
сертификации; чтобы браузер не предупреждал, установите корневой сертификат:

```bash
docker compose cp nginx:/etc/nginx/certs/ca.crt .
```

## 3. Загрузка материалов заказчика

Положите файлы заказчика в каталог `data/organizers/` (классификатор происшествий, памятку,
билеты) и выполните:

```bash
docker compose exec backend python -m app.importers.organizers
docker compose exec backend python -m app.seed
```

Импортёр идемпотентен: повторный запуск не создаёт дубликатов. Итог разбора записывается в
`docs/DATASET.md`.

## 4. Модели искусственного интеллекта

```bash
./scripts/fetch_models.sh          # требуется интернет, около 10 ГБ
docker compose --profile ai up -d
```

Скрипт скачивает модель для выбора реплик заявителя, модель для генерации сценариев, модель
распознавания речи и голоса синтеза. Перечень и контрольные суммы лежат в
`scripts/models.manifest`, лицензии перечислены в `docs/LIBRARIES.md`.

Настройки в `.env`: `LLM_DIALOG_MODEL`, `LLM_GEN_MODEL`, `STT_MODEL`, число потоков `LLM_THREADS`,
режим диалога `DIALOG_MODE`.

## 5. Телефония

```bash
docker compose --profile telephony up -d
```

В `.env` задать `TELEPHONY_ENABLED=true`, внешний адрес сервера `TELEPHONY_EXTERNAL_IP`, диапазон
медиапортов `TELEPHONY_RTP_START` и `TELEPHONY_RTP_END`, порт SIP `SIP_PORT`, пароль интерфейса
управления `ARI_PASSWORD`.

На межсетевом экране открыть: порт SIP (по умолчанию 5060, UDP и TCP) и диапазон медиапортов (UDP).

**Софтфон в браузере** настраивается автоматически: учётная запись обучающегося создаётся вместе с
пользователем, данные приходят при входе.

**Настольный IP-телефон** (например, РТУ Т16Р): в настройках аппарата указать адрес сервера
(адрес узла телефонии), имя пользователя и пароль из карточки обучающегося в кабинете
администратора, кодеки G.722 и PCMA, регистрация по UDP.

Если телефония выключена (`TELEPHONY_ENABLED=false`), занятия работают полностью: вызов
имитируется в интерфейсе, речь передаётся через микрофон браузера.

## 6. Установка без доступа в интернет

На машине с интернетом:

```bash
./scripts/fetch_models.sh
docker compose --profile ai --profile telephony pull
docker save $(docker compose config --images) -o images.tar
tar czf models.tar.gz models/
```

Перенести `images.tar`, `models.tar.gz`, репозиторий и каталог `data/organizers/` на носитель.
На сервере в контуре:

```bash
docker load -i images.tar
tar xzf models.tar.gz
docker compose up -d
```

## 7. Резервное копирование и восстановление

Копии создаются ежесуточно сервисом `backup` в том `backups`; время задаётся `BACKUP_TIME`,
число хранимых копий `BACKUP_KEEP`. Копию можно создать вручную в кабинете администратора.

Проверка восстановления:

```bash
./scripts/restore_test.sh
```

Скрипт разворачивает последнюю копию в отдельную базу и проверяет, что данные читаются. Полное
восстановление: остановить приложение, восстановить базу из копии, распаковать файлы тома
`storage`, запустить приложение.

## 8. Обновление

```bash
git pull
docker compose up -d --build
docker compose exec backend alembic upgrade head
```

Миграции базы выполняются автоматически при старте бэкенда; команда нужна только при ручном
обновлении.

## 9. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Браузер предупреждает о сертификате | Установить корневой сертификат из тома `certs` |
| Звонок не приходит в браузер | Проверить `TELEPHONY_ENABLED`, профиль `telephony`, доступность порта SIP и диапазона медиапортов |
| Заявитель отвечает не по теме или молчит | Проверить, что поднят профиль `ai` и модели скачаны; при недоступной модели система переходит на утверждённые реплики и сообщает об этом |
| Оценка не проверяет грамотность | Недоступен сервис `languagetool`: составляющая помечается «не проверено», остальная оценка работает |
| Долгий первый ответ после запуска | Модели прогреваются; повторные ответы быстрее |
| Не хватает памяти на ноутбуке | Запускать без профиля `ai` |
