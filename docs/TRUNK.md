# Внешний SIP-транк оператора связи

Как подключён транк, как проверить и как развивать. Транк это опция: учебный контур работает
без него, все звонки занятия идут внутри сервера. Транк нужен, чтобы система звонила на настоящие
телефоны и принимала звонки с городских номеров.

## Что уже работает

Проверено на стенде 27.09.2026 живым звонком: сервер зарегистрировался в МегаФоне и дозвонился
на мобильный, телефон зазвонил и определил номер линии.

- регистрация учётной записи оператора связи в Asterisk;
- исходящий вызов на любой номер через транк;
- входящий вызов с городского номера;
- звонки занятия на телефон обучающегося (#234), см. «Звонки занятия через транк».

## Как это устроено

Конфигурация транка не лежит в репозитории статично, а собирается при старте контейнера
телефонии скриптом `deploy/asterisk/render-config.sh` из переменных окружения. Если переменные
пустые, блок транка не создаётся и телефония работает как прежде. Учётные данные живут в `.env`
на сервере и в репозиторий не попадают.

Что генерируется в `/etc/asterisk/generated/trunk.conf`:

- `trunk-auth` — логин и пароль у оператора;
- `trunk-reg` — регистрация на сервере оператора;
- `trunk-aor`, `trunk` — сам endpoint транка, кодеки, симметричный RTP;
- `trunk-identify` — распознавание входящих по адресу оператора.

План набора (`deploy/asterisk/extensions.conf`):

- контекст `trunk-out` — исходящие: `Dial(PJSIP/<номер>@trunk)`;
- контекст `trunk-in` — входящие: если задан `TELEPHONY_TRUNK_INBOUND`, звонок идёт на телефоны
  этого обучающегося, иначе его забирает бэкенд (см. ниже);
- `trainee-targets` — кого звать на звонок занятия: софтфон, настольный телефон и, при
  включённом транке, собственный телефон обучающегося через `trunk`.

## Настройки в .env

```
TELEPHONY_TRUNK_USER=79001234567          # номер или логин у оператора
TELEPHONY_TRUNK_PASSWORD=...              # пароль SIP
TELEPHONY_TRUNK_DOMAIN=multifon.ru        # домен регистрации
TELEPHONY_TRUNK_PROXY=sbc.megafon.ru:5060 # узел оператора
TELEPHONY_TRUNK_CODECS=alaw,ulaw          # кодеки
TELEPHONY_TRUNK_INBOUND=                  # логин обучающегося для входящих; пусто = эхо линии
```

Пустые `USER`, `PASSWORD` или `DOMAIN` означают, что транк выключен.

## Что открыто на сервере

Межсетевой экран стенда (`ufw`): порт `5060/udp,tcp` для SIP и диапазон `10000-10100/udp` для
голоса. Диапазон совпадает с `TELEPHONY_RTP_START`/`TELEPHONY_RTP_END` в `.env`. Внешний адрес
сервера задан в `TELEPHONY_EXTERNAL_IP`, без него голос в одну сторону не пойдёт.

## Как запустить и проверить

```bash
cd /opt/lct/app
docker compose --profile telephony up -d asterisk        # после правки render-config.sh добавить --build

# регистрация должна быть Registered
docker compose exec asterisk asterisk -rx "pjsip show registrations"

# сгенерированная конфигурация транка
docker compose exec asterisk cat /etc/asterisk/generated/trunk.conf

# тестовый исходящий вызов (замени номер)
docker compose exec asterisk asterisk -rx \
  "channel originate Local/79XXXXXXXXX@trunk-out application Playback demo-congrats"
```

Если регистрация не проходит, смотреть `docker compose logs asterisk` на предмет `403` или
`registration failed`. Частые причины: неверный пароль, учётка в режиме lite (оператор запрещает
регистрацию сторонним оборудованием), закрытые порты.

## Ограничения оператора (МультиФон Бизнес МегаФон)

- не больше трёх одновременных регистраций на учётную запись; софтфон и сервер считаются
  отдельно, при тесте лишние регистрации снимать;
- голосовые порты на стороне оператора 10000-27999;
- пароль SIP можно запросить командой `*137#` с самой симки или сообщением на 1117.

## Звонки занятия через транк (#234)

Работает так же, как МультиФон облачного контура (docs/MULTIFON.md), только через транк
локального Asterisk и без облачного голоса.

1. Бэкенд видит `TELEPHONY_TRUNK_USER` (передаётся ему в docker-compose) и разрешает галочку
   «Звонки на телефон» в занятии. Без телефонии или без транка галочка недоступна.
2. Обучающийся вводит свой номер на странице занятия, либо администратор задаёт его в таблице
   «Телефоны стажёров».
3. Все звонки занятия (заявитель на 112, звонок диспетчера в службу, доклад бригады, обратный
   звонок заявителю) звонят одновременно в браузер, на настольный телефон и на мобильный через
   транк. Кто ответил первым, тот и разговаривает. На мобильном определяется номер линии, а не
   номер из сценария.
4. Обучающийся может сам позвонить на номер линии со своего телефона: бэкенд найдёт вызов,
   который сейчас для него звонит, и отдаст его этому звонку. Если ничего не звонит или номер
   незнаком, звонок сбрасывается. Эхо-проверки линии на входящем больше нет, линию проверять
   исходящим вызовом из консоли (см. выше).
5. Разбор и баллы не зависят от канала: разговор пишется в те же диалог и звонки в службы.

`TELEPHONY_TRUNK_INBOUND` по-прежнему отправляет все входящие одному обучающемуся, мимо бэкенда.

## Что дорабатывать

- живой прогон серии звонков занятия через транк на стенде;
- настольный IP-телефон (РТУ Т16Р) уже звонит вместе с софтфоном (`phone-<логин>`), его
  регистрацию нужно проверить на реальном аппарате.
